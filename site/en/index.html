What git-qa is

The AI never passes anything. A pass appears only when a person presses the key.

git-qa is not a tool for handing QA to an AI and having it say "all green". When something goes wrong, a person is accountable, and "the AI did it" is not an answer. What git-qa does is keep the person accountable while making that accountability cheaper: the AI prepares what to look at and narrows down where to look, instead of judging in your place.

  • Passes and "the AI went through it" are never mergedVERIFIED means a person looked. AUTO_PASS means the AI went through it and nobody looked. Neither collapses into a plain PASS.
  • The live view is the primary mediumYou watch the AI operate, as it happens, instead of scrubbing through recordings afterwards.
  • You look at three things onlyCases the AI could not judge, cases that changed since last time, and failures. The rest stays AUTO_PASS.
  • Test sheets are TSVWrite them in any spreadsheet: one case per row, steps and expected result. git-qa never writes back to the sheet.
  • Evidence is a folder you can commitrun.json plus a screenshot and optional video per case. No machine-specific paths or personal names, so it looks the same on anyone's machine.
  • Everything stays on your machineThe target's screen and the evidence never leave the PC.
Features

The AI runs the sheet and stops when it is your turn

Watch the live view, sign off with one key

The AI follows the steps in the sheet (click, reload, click again). When it finds the expected text on screen it marks it in red and stops. You press D to pass or F to fail; the case becomes VERIFIED with your handle and the run moves on.

  • A cannot judge (BLOCKED), S skip this time (SKIP)
  • Space moves on without a verdict: the case stays AUTO_PASS, never promoted to a pass

Four kinds of target

Android devices and emulators over USB (adb), web pages in Chrome, Edge, Firefox or Safari at the same width, desktop apps on macOS and Windows, and iPhone / iPad mirrored over USB.

For web you pick an installed browser and its version goes into the evidence. On macOS, desktop apps are pressed without bringing them to the front, and text is read in two passes: accessibility first, then OCR.

What is left behind

run.json is written after every case: verdicts, steps, who signed off and when. Each case keeps the screen at the moment of the verdict and, if you chose to record, a video. For web pages the URL at verdict time is kept too, with query values masked.

Sheet paths are stored relative to the workspace, so the folder looks the same on anyone's machine and can be committed. When the run is over, one button opens the evidence folder in your file manager. 

runs/<timestamp>/
  run.json        … verdicts, steps, who signed off and when
  case-001/
    screen.webp   … the screen at the moment of the verdict
    screen.webm   … video while the AI operated (if recording was on)

Unattended runs, and resuming the next day

Watch mode keeps going without key presses: the AI runs to the end and anything you did not press stays AUTO_PASS. With --no-ui a sheet can run overnight with no window at all; in the morning a person looks only at what failed.

Stop a run and pick it up the next day: cases that were not run are not written, and if the sheet changed in between, the run will not resume, because yesterday's verdicts were placed against different wording.

  • D
    PassI looked and it is right. Recorded as VERIFIED
  • F
    FailI looked and it is wrong. Recorded as FAIL
  • A
    Cannot judgeRecorded as BLOCKED
  • S
    Skip this timeRecorded as SKIP
  • ␣
    Next, no verdictStays AUTO_PASS
  • Esc
    StopCases not yet run are not written

For AI agents, over MCP

Agents such as Claude Code can take a screenshot, read the screen text, list what can be tapped, tap, swipe and type, on Android, web, desktop and iPhone. git-qa is listed in the official MCP registry.

There is no tool that places a verdict. The moment an AI could write VERIFIED, the point of the tool would be gone. 

$ pnpm mcp                                                    # Android (default)
$ GIT_QA_MCP_TARGET=web GIT_QA_MCP_URL=http://localhost:3000/ pnpm mcp
$ GIT_QA_MCP_TARGET=desktop GIT_QA_MCP_APP=Notes pnpm mcp

tools: element_list / element_tap / device_screen_text / device_screenshot …
no tool places a verdict. Only a person passes a case.

Getting started

Four steps

  1. Install

    Pick the installer for your OS above. Node.js 22 or later is required as well.

  2. Enter a handle

    It goes into the evidence as "who looked". Use a handle rather than your real name; the evidence is designed to live in a public repository.

  3. Pick a target and a sheet

    An adb device, a web page URL or a desktop app name, plus a test sheet (TSV). Samples are in sheets/.

  4. Watch and press

    Start the run. The AI works through the cases and stops when it is your turn; D or F moves on.

FAQ

Frequently asked questions

What does git-qa do?

An AI works through a test sheet (TSV) on an Android device, a web page, a desktop app or an iPhone, and a person watches the live screen and presses one key per case to place the verdict. Who looked, and when, is recorded in the evidence (run.json) together with the screen at that moment.

Does the AI pass cases?

No. The most the AI can give is AUTO_PASS, which means the AI went through it and nobody looked. VERIFIED, meaning a person saw it and vouches for it, appears only when a person presses the key, and their handle goes into the evidence.

What do I need to run it?

macOS (Apple Silicon or Intel) or Windows (x64 or ARM64) with Node.js 22 or later. adb if you test Android devices, and one of Chrome, Edge, Firefox or Safari if you test web pages. ffmpeg and cwebp are optional. The installers are free and the source is MIT licensed.

Does anything leave my machine?

No. The target's screen and the evidence stay on your PC. The evidence contains no machine-specific paths or personal names, so the folder can live in a git repository.

What works on Windows?

Web pages, Android devices and desktop apps. Desktop apps are read and pressed through UI Automation. Recording needs ffmpeg, and iPhone from Windows is unverified. The Windows installers are not code-signed.

Can an AI agent use it?

Yes. Over MCP, agents such as Claude Code can take a screenshot, read the screen text, list what can be tapped and tap it, on Android, web, desktop and iPhone. You can run a sheet unattended overnight (--no-ui) and have a person look only at what failed in the morning.
