## この製品で、壊してはいけない 1 本

**合格は人が置く。AI は `AUTO_PASS` まで。**

| 値 | 意味 |
|---|---|
| `VERIFIED` / `FAIL` | **人が実物を見て置いた** |
| `AUTO_PASS` | **人は見ていない。**道具の判定のまま送った |
| `BLOCKED` | 人にも判断できない／操作へ落とせない |
| `SKIP` | 今回は見ない |

**`PASS` という値を作らないこと。**作った瞬間、上の 2 つが 1 つに潰れます。
**それを防ぐためだけに、この製品は在ります**（C1 / C17）。

**MCP に判定を置く道具を載せないこと。**載せた瞬間、AI が「人が見た」と書けます。
**要望として来ても、これだけは通りません。**

**派生する決めごと 3 つ**

- **できないことを `FAIL` にしない**（C20）。**持っていないと言う。**
  `unsupported` / `BLOCKED` ＋ 理由で残す
- **黙って空を返さない。**「無い」と「読めない」を混ぜない
- **「動く見込み」を実測の欄に書かない**（C56）。
  `README` の表に `✅ 実測` と書けるのは、**動かして確かめた分だけ**

## 踏んだ穴（**ここがこの文書の本体**）

**どれも「テストは緑なのに実物で壊れていた」**類です。**同じ所を踏まないために残します。**

### 1. 入口が 2 本ある

**`#37`。**`行き先` を足したとき、**同じ入口が 2 本あることに気づかなかった。**

```
headless.ts（--no-ui）     sheetDestination を見ていた  ← 正しい
run-session.ts（人が見る）  meta['対象'] を素通し        ← 抜けていた
```

**こちらは `--no-ui` でばかり試していたので、人が見る道の不具合を最後まで踏まなかった。**

**対策。****機能を足すときは、同じ入口が何本あるかを数える。**
**そして両方の道で走らせる**（`--no-ui` と、画面から始める道）。

### 2. 直した側で、同じ形を作りかける

**`#41`。**「押せるものを先に選ぶ」を入れた直後、
**押せるボタンが `disabled` のとき、押せない見出しへ落ちて `FAIL`** にしていた。
**`AUTO_PASS` にはならなかったが、「製品が悪い」ように見える**点で同じ間違え方だった。

**対策。****直したら、直した形で実物を 1 回流す。**単体試験は通っていた。

### 3. 文書が、実装より先に古くなる

**`C77`。**一度に **8 箇所**が実装と食い違っていた。いちばん悪かったのはこの 1 行。

```
ログインが要る画面は、シートの 1 件目からログイン手順を書いてください
```

**これは「ID とパスワードをシートに書くことになる」と言われて直した所**だった。
**実装は直っていたのに、文書だけが禁じられたやり方を案内し続けていた。**

**`docs/agent-brief.md` は、MCP の `about` がそのまま返します。**
**古いと、全部のエージェントに古い前提が渡ります。****README より重い所です。**

**対策。**コードを変えたら、**同じ commit で文書を直す**（§10）。
**版を数本出したら、文書の食い違いを数え直す。**

### 4. 手順書は、実行者が飛ばせる

**`C78`。**別の開発機の clone が **`beta.3` で止まっていた**（11 版・約 5 日）。
その機械には **Windows の起動修正すら入っておらず、配った版が 368ms で死ぬまま**だった。
**誰も気づかなかった。**

`docs/dev-check.md` に「まず `git pull`」と書いた。**それだけでは足りない。**
**`pnpm doctor` の 1 行目で測る**ようにした。

**対策。****守ってほしいことは、文ではなく測定値にする。**

### 5. 「動く見込み」が、いつのまにか実測になる

**`C56`。**iOS は**叩きが入っているが、実機で 1 行も測っていない。**
**`README` / `dev-check` / `decisions` の全部に「未実測」と書いてある。**
**配布ページ（`site/index.html`）には載せていない** —— 未実測を配布ページに書くと、はったりになる。

**対策。**実測の表には**動かして確かめた分だけ**。**測っていないものは、測っていないと書く。**

### 6. 起こしたものが溜まる

**`C66`。**切り分けのために検証用 Chrome を**30 個溜めた**ことがある。
`kill` すると子が残るので、**繰り返した分だけ溜まる。**

**対策。****起こす前に人へ断る。終わったら数える。**

```bash
ps -Ao command | grep 'git-qa-web-' | grep -vc grep   # 0 になるまで
pgrep -x git-qa-desktop | wc -l
```

**落とすのは使い捨てプロファイルのものだけ。人が普段使っているブラウザには触らない。**

### 7. 決定を覆すとき、古いほうが根拠として残る

**`C80` が `C72` を覆した。**「普段使いのプロファイルを止めない」と決めていたが、
**その理由（専用プロファイルは既定の置き場の中に居る）が実測で消えた。**

**対策。**覆したら、**古い項に追記する**（消さない）。
**追記が無いと、後から読む人が古い判断を根拠にします。**

### 8. プロダクトが複数あると、「どれの話か」は文から決まらない

**`C74`。**別プロダクト（デスクトップアプリ）の話を、**git-qa の決定として書いてしまった。**
すぐ訂正が入ったが、**決定は実装の前提になる**ので、**取り違えたまま残すと危ない。**

**対策。****決定として書く前に、どのプロダクトの話かを確かめる。**

### 9. 網のせいにして、自分のバグを見逃す

**2026-09-24。**Issue へ告知を出す繰り返しが全部失敗し、**「網が落ちている」と報告した。**
実際は**こちらのバグ**だった —— **zsh は `$pair` を語分割しない**ので、
`gh api .../issues/$1/comments` の番号が **`39 r39`** になっていた。

**網が本当に不安定だった**ので、**間違った説明のほうが、もっともらしかった。**

**対策。****「外のせい」を報告する前に、自分のコマンドを 1 回疑う。**
**失敗した実際の呼び出しを 1 回だけ、そのまま目で見る**（`set -x` でも、echo でも）。
**同じ失敗が「全部」なら、外より自分のほうが疑わしい**（外なら、ふつう揺れる）。

## この機械・この案件の事情

- **網が不安定です**（2026-09-21 / 24 に何度も切れました）。
  **`git` の口と API の書き込みが、別々に落ちたり戻ったりします。**
  読みだけ通る時間帯があるので、**REST で読んで、書き込みは粘る**のが速いです
- **commit は AI、push は人間**（§6）。
  **担当者が離れているときは、指示をもらってから代行**しました。**自分から代行を提案しない**
- **試験導入の方の報告が、この製品をいちばん速く直しています。**
  **実測つきで来ます。**そして**こちらの設計判断が覆ったことが 2 回あります**（C80 / C82）。
  **「こちらが正しい」から始めないこと**
- **要望は、使った人がその場で自分の言葉で書く**（§27）。**要約しないこと**

```markdown
## 決めたこと
## 根拠
## 採らなかった案とその理由
## これを止めるべき条件
## 実行状況
```

**`.claude/decisions.md` の C64 以降が、全部この形で書いてあります。**
**書き方に迷ったら、直前の項を真似してください。**
