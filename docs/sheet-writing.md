# 検証シートの書き方（AI エージェント向け）

> **MCP の `sheet_guide` はこの文書をそのまま返します。**
> **人向けの案内は `docs/alpha-guide.md`。**

**シートを書く前に、これを読んでください。**
**ここに書いてあることは、全部 2026-09-24 に実際に踏んだ失敗から来ています。**
**同じ日に、同じ人が 3 回、雑なシートを書きました。**

---

## いちばん大事な 1 つ

> **期待結果に、押す前から画面に在る文字を書かない。**

この道具の期待結果は **`「X」と表示される`** だけです。**在るか、しか見ません。**
**押す前から在る文字を書くと、何も起きなくても通ります。**

```
✗ 「🌐 English」をクリックする  →  「English」と表示される
                                    ^^^^^^^ ボタンに最初から出ている。押さなくても通る

✓ 「🌐 English」をクリックする  →  「日本語」と表示される
                                    ^^^^^^ 一覧が開いて初めて出る
```

**自分に聞いてください。「押す前にこの文字は画面に在るか？」**
**在るなら、その行は何も確かめていません。**

---

## 期待結果は、**人が見る画面**から取る

**アクセシビリティの木や DOM から取らないこと。**

```
木にある     Connections        画面にある  CONNECTIONS      ← CSS で大文字に変形
木にある     日本語 JA          画面にある  「日本語」と「JA」が別々の要素
```

**木から取った文字で書くと、AI は木と突き合わせて通します。**
**同じ源から取ったものどうしを比べるので、一致して当たり前です。**
**そして人が見ると、そこに無い。**

**検査が検査対象と同じ源を見ていると、必ず通ります。**

**取り方**: **実物の画面を見る。**絵を撮って、**そこに読める形で写っている文字**を書く。

---

## 読める大きさの文字を選ぶ

**判定するのは人です。**映像で読めない文字は、**判定できません。**

```
✗ 「CONNECTIONS」        画面の隅の小さな灰色の見出し。映像では読めない
✓ 「テーブル・カラムを検索」  入力欄の中。読める大きさ
```

（人は映像を拡大できます。それでも、**最初から読める所を選ぶほうが速い**）

---

## 項目は「人が何をできるか」で書く

**道具の都合を書かない。**

```
✗ 選択肢が開く / 選択肢を選べる          ← 仕掛けの話
✓ 表示言語を日本語に変えられる           ← 人ができること
```

**証跡を読むのは、半年後の別の人**です。**そのとき意味が残るのは後者だけ**です。

---

## 報告された不満を、そのまま行にする

**直した仕掛けを確かめて、困っていたことを確かめない**——これがいちばん多い失敗です。

報告がこうだったとき、

> 押すたびに前面へ戻すので、**開いているものが畳まれる**。**アプリが前面にきて操作できない**

**「開く」「選ぶ」だけ書いて、「畳まれない」「前面を奪わない」を書かなければ、
その報告は 1 行も確かめていません。**

**機械に判定できない行も書いてよい**（むしろ書くべき）。
`手順` が操作へ落とせなければ AI は **`BLOCKED`** を出し、**そこに人が判定を置きます。**
**それがこの道具の正しい使い方**です。

```
2  開いた一覧が、畳まれずに残る   画面を見る   一覧が開いたままである
3  アプリが前面に出てこない       画面を見る   アプリは前面に出ていない
```

---

## 前提を書く

**シートは、ある状態から始まります。**書かないと、**次に走らせた人が違う状態で走らせます。**

```
# 前提: 英語表示で起動していること。git-qa 以外の窓を前面に置いてから始めること
```

**検証で変えたものは、検証で戻す。**最後の行で元の状態へ戻すと、**何度でも走らせられます。**

---

## 1 回目だけ通る、を防ぐ

**同じ操作を 2 回**書くと、**1 回目だけ効く不具合**が出ます。

```
1  一覧を開ける          …
5  変えたあとも開ける    …    ← これが無いと「1 回目だけ開く」を見逃す
```

---

## 見出しに書けるもの

| 見出し | 何 |
|---|---|
| `# 対象:` | **何を検証したか**（リポジトリ名でもよい。証跡に残る） |
| `# 行き先:` | **何処を見るか**（URL / アプリ名）。無ければ `対象` を見る |
| `# 前提:` | 始める前の状態 |
| `# 待つ:` | **期待結果が出るまで待つ長さ**（既定 2 秒）。`8s` / `8秒` / `8` / `8000ms`・上限 120 秒 |
| `# 日付の書き方:` | 画面に出る日付の形（`YYYY-MM-DD` など） |

**押すとサーバを 1 往復する行**（ログイン → 遷移、採番してから遷移）では、
**`# 待つ:` を延ばさないと落ちます。**製品は正常なのに `FAIL` が出ます。

---

## 手順に書ける言い方

| 書き方 | すること |
|---|---|
| `アプリを起動する` / `ページを開く` | 見出しが宣言した先を開く |
| `「保存」をクリックする` / `「保存」をタップする` | その文字の場所を押す |
| `「保存」を押す` | 同じ。**鉤括弧が要る**（`Enter を押す` と区別するため） |
| `「お名前」に「テスト太郎」と入力する` | その欄へ打つ |
| `「A」を「B」へドラッグする` | 掴んで運ぶ |
| `Enter キーを押す` | キーを送る |

**上のどれでもない手順は `BLOCKED` になります。**それでよいときは、そのまま書いてください
（**人が操作して、人が判定を置きます**）。

---

## 期待結果に書ける言い方

**`「X」と表示される` だけ**です。

- **鉤括弧は 1 つだけ。**2 つ以上あるとどちらを見るか決まらず、0 個なら見る文字列がありません
- **否定は書けません**（`「X」が表示されない` は通りません）
- **変化も書けません**（`X から Y に変わる` は書けません）

**だから「押す前に無い文字」を選ぶことが、そのまま「変化を見る」ことになります。**

---

## 押す場所の決まり方（知っておくと、書き方が変わる）

- **押せるもの（ボタン・リンク）を先に選びます。**同じ文字が見出しにもある画面で、
  見出しを押してしまう事故を防ぐため
- **押せない状態**（`disabled` など）のものしか無ければ、**押さずに `BLOCKED`** になります
- 同じ文字が複数あるときは、**いちばん内側の小さいもの**
- **行の指定は書けません**（「2 番目の」とは書けない）

---

## 人が読んで分かる文言にする（**ここは足していく所**）

**シートは人が読んで判定します。**機械に通ることと、人に伝わることは別です。
**実際に指摘されたものを、ここへ足していきます。**

> **書く側の心得。**ここへ足すときは、**案件名・製品名・個人名・接続先・アイパスを書かない。**
> **言い回しの型だけ**を残す（`product-baseline.md` §14 / §25）。
> **指摘した人の言葉を、そのまま型にする** —— 要約すると、困っていた所が落ちます。

### 指摘の記録

| 日 | 直す前 | 直したあと | なぜ |
|---|---|---|---|
| 2026-09-24 | `Connections` と表示される | `CONNECTIONS` と表示される | **木にある文字と、画面に出ている文字が違う**（CSS で大文字に変形されていた） |
| 2026-09-24 | `日本語 JA` と表示される | `日本語` と表示される | **木が 2 つの要素を 1 本に合成していた。**画面では「日本語」と「JA」が別々 |
| 2026-09-24 | `English` と表示される | `日本語` と表示される | **押す前からボタンに出ていた。**押さなくても通る |
| 2026-09-24 | 項目「選択肢が開く」 | 項目「**表示言語を日本語に変えられる**」 | **道具の都合ではなく、人ができること**で書く |
| 2026-09-24 | （無し） | 「**開いた一覧が、畳まれずに残る**」「**アプリが前面に出てこない**」 | **報告された不満が 1 行も入っていなかった。**直した仕掛けだけ見ていた |

### 人が言った、より良い言い方

**人はこう書きます。**

> プルダウンが開き、**2 番目に**日本語が表示されている

**この道具はここまで書けません**（`「日本語」と表示される` だけ）。
**書けないことは、書けないと知っておく** —— そのぶん、**項目名となぜ見るのかで補います。**

---

## 書き終わったら、自分に 5 つ聞く

1. **期待結果の文字は、押す前に画面に在るか？**（在るなら書き直す）
2. その文字は、**実物の画面**から取ったか？（木や DOM から取っていないか）
3. その文字は、**映像で読める大きさ**か？
4. **報告された不満**が、行になっているか？
5. **前提**を書いたか。**最後に元へ戻るか。**
