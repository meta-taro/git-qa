# feedback — 改善要望シート共通テンプレート（正本）

全配布リポ共通の改善要望シート雛形。ルールの正本は `rules/product-baseline.md` **§36**。

| ファイル | 用途 |
|---|---|
| `improvement-request-ja.tsv` | リリース後の改善要望・不満・良かった点の受け皿。デスクトップアプリのグリッドで開く |

## §22 の検証シートと何が違うか

**形式は同じカスタム TSV だが、書く人が逆。**

| | §22 検証シート | §36 改善要望シート |
|---|---|---|
| 何を見るか | **仕様どおり動くか** | **使ってどうだったか** |
| 行を起こす | AI | **使った人（人間）** |
| ファイル数 | 対象機能ごとに 1 枚（`<NNN>-<slug>.tsv`） | **1 リポ 1 枚**（`improvement-request.tsv`） |
| AI が触ってよい列 | `関連Issue` | `状態` と `関連Issue` の 2 列だけ |

仕様どおりに動いていても使いにくいことは普通にある。検証シートはそこを拾わないので、器を分けている。

## 配布のされ方

`/push-project` が本ディレクトリを配布リポの `.claude/templates/feedback/` へコピーし、
**さらに `docs/feedback/improvement-request.tsv` として実体を 1 枚置く**。

ここが `templates/test-spec/` と扱いが違う点で、意図的にそうしている。
**検証シートは AI がその都度起こすが、改善要望シートは使った人が書き足す器**なので、
最初から実ファイルが無いと「どこに書けばいいか分からない」で手が止まる。

## 触るときの注意

- 1 行目 `#! md-business:test-spec-tsv/v1` は**行頭 0 桁**。マジック行は検証シートと共通（形式が同じもの）。
- セル区切りは**実タブ**。**タブが 1 個足りないと内容が左隣の列に黙って入り、`validateTsv` も素通りする**。
  テキストエディタで手打ちせず、グリッド編集か MCP の `update_tsv_row` で書く。
- セル内改行は `\n`（バックスラッシュ + n）。実改行を入れると行がずれる。
- 見本の 2 行は `備考` に「見本の行。消して構いません」と入れてある。配布先で消してよい。
- 変更したら md-business の `packages/schema-test-spec-tsv/dist` の `parseTsv` / `validateTsv` に通す。
  2026-08-04 実測: cols=12 / rows=2 / issues 0 / round-trip 一致。

## 列を足したくなったら

**足す前に「その列が空欄のまま埋まらない可能性」を考える。**
書くのはエンジニアとは限らず、列が増えるほど 1 行足すコストが上がって、結局誰も書かなくなる。

現在の必須列は `No. / 起票日 / 起票者 / 種別 / 何をしていたか / どうなったか` の 6 つ。
**原因・再現手順・優先度は意図的に必須にしていない**（書けない人が出るため）。

## 変更手順

テンプレート・配置規約・命名規約は**全リポ共通**。変更は企画側リポで決定し、各リポへ Issue で通達する（§36 関連）。
