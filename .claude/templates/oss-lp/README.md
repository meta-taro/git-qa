# OSS の入口ページ 骨組み

`index.html` / `style.css` が正本。各 OSS リポの GitHub Pages はこれに寄せる。

## なぜ作ったか（2026-09-22 実測）

7 枚の GitHub Pages を 1440px で開いて横に並べた。

| | h1 に出ているもの | 実物の絵 | lang |
|---|---|---|---|
| zumen | **困りごと**（構成が変わった。図はそのままだ。） | あり | ja/en 切替 |
| git-qa | 製品名 | あり | ja |
| dbboard | 製品名 + 対応 DB の列挙 | あり | en |
| sshboard | 製品名 | なし | en |
| warifu | 製品名 | なし | ja |
| md-business | 製品名 | なし | en |
| modern-map-japan | 手法名 | 地図が黒い | ja |

伝わらない原因は、ページごとの出来ではなく 2 つだった。

1. **h1 が製品名になっている。** 読み手はまだその名前を知らないので、
   いちばん大きい行が情報ゼロになる。zumen だけが困りごとから入っていて、
   7 枚の中で最も伝わる。**zumen が正解で、他 6 枚が旧型。**
2. **7 枚が別々の作りに見える。** lang が en3/ja4、og 画像が専用 1・スクショ 1・
   アイコン 3・無し 2、言語切替が select / テキスト / 無しで三様。
   同じところが出している道具に見えないので、信用が積み上がらない。

## 順番を入れ替えない

骨組みの中身は見た目ではなく**順番**。

1. 名乗り（アイコン + 製品名 + 言語）
2. **困りごと**（h1・2 行）
3. どう消すか（lede・2 行）
4. 入手口（ボタン + 対応 OS・ライセンス）
5. **実物 1 枚**
6. 本文（最初の section は「なぜそれが起きるのか」）

1〜5 がスクロールせずに見える範囲。**ここで伝わらなければ以下は読まれない。**

よくある壊し方:

- **「落とす」「Download」を 5 より前に出す。** 何の道具か分かっていない人に
  署名や公証の話をすることになる（warifu / sshboard が今この形）
- **h1 を製品名に戻す。** 名前はアイコンの隣で足りる
- **実物の絵を省く。** 「絵がまだ無いので文章で」は、いちばん効く 1 枚を捨てている
- **版数を書く。** 書いた翌日に嘘になる。版はリリースページが持つ

## 書くときの決まり

- **h1 に製品名・技術名・「〜な人のための」を入れない。**
  読み手にすでに起きていることだけを書く
- **lede は 2 行。** 2 行目に効き目を置いて `<b>` で締める
- **figcaption は絵の説明を書かない。** h1 の困りごとと絵を結ぶ 1 文を書く
- **「まだ出来ていないこと」の節を必ず置く。** 隠すと、入れてから気づくことになる
- **日本語と英語を両方出す。** 作った側も外部の読み手も同じ URL を踏む。
  どちらを `/` に置くかは、そのリポが既に公開している URL を動かさない側で決める
- **製品固有の部品を `style.css` へ足さない。**
  ギャラリー・絞り込み・地図は各リポの `extra.css` に置く。
  ここへ足すと配った先全部がその製品の都合を背負う

## このフォルダの扱い

- `index.html` / `style.css` / この README は**同期で上書きされる**。ここを直接書き換えない
- LP 本体は Pages の公開フォルダへ**複製して**作る。製品固有の部品は `extra.css` に置く
- このフォルダ自体を Pages の公開元にしない
