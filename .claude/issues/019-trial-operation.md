## 人が決めたこと（2026-09-07・**言葉のまま**）

> 一旦試験運用は連絡くんという開発中デスクトップアプリと、ベガスギフトという開発中ウェブサイトで
> 考えています。この2つは私が担当していてｗ，ここで試験運用で、ブラッシュアップされたら、
> 別のウェブサイト開発中案件に試験運用として使ってもらいます。

## なぜこの選び方がよいか

**自分が担当している 2 つで先に踏む。**詰まったときに、原因を追える人がその場にいる。
他人の案件で先に踏むと、「道具が悪いのか、案件が特殊なのか」が切り分けられない。

**そして 2 つで種類が違う。**片方がデスクトップ、片方がウェブ。
**両方の道が実務で当たる。**

| | 種類 | 使う道 |
|---|---|---|
| **連絡くん** | デスクトップアプリ（開発中） | `adapter-desktop`（AX → OCR） |
| **ベガスギフト** | ウェブサイト（開発中） | `adapter-web`（Chrome / Firefox / Safari） |

そのあと**別のウェブ案件へ渡す** —— **他人が使って初めて、案内が足りているかが分かる。**

## 着手前に塞いだこと（2026-09-07）

**配布物からデスクトップ検証が選べなかった。**`pnpm run:sheet:desktop` はターミナルの話で、
**連絡くんを試すには足りていなかった。**

- 画面の「1. 見る相手を選ぶ」に**アプリ名の欄**を足した
- 実行器は形で見分ける（`http(s)://` ならウェブ、`app:` ならデスクトップ、それ以外は端末）
- **絵から文字を読む道具（段 2）を配布物へ同梱した。**
  それまでは環境変数で外から渡す形で、**配った先では段 2 が使えなかった**

## 見たいこと（試験運用で）

- **どこで止まるか。**止まった文が、そのまま人に届いているか
- 手順の語彙が足りているか（**足りない書き方が出たら、そこで足す**・C40）
- 同じ文字が複数あるとき（一覧の「削除」が 10 個など）に、どう書きたくなるか
- ログインが要る画面で、毎回まっさらなプロファイルが邪魔にならないか
- デスクトップで、段 1（AX）が空のときに段 2（OCR）で足りるか

## 渡し方（2026-09-07・**dmg をやめた**）

**当初は dmg を渡すつもりだった。**署名・`xattr -dr com.apple.quarantine`・Release の作成・
`0.0.0` という版番号 —— **どれも試験運用の本題ではない。**

人の指摘で前提が変わった。

> あの、向こうのデバイスにも割符のクローンリポジトリがあるんですよ

**git-qa は public。**なら渡す物は要らない。**クローンして動かしてもらえばよい。**

```bash
git clone https://github.com/meta-taro/git-qa.git
cd git-qa && pnpm install
GIT_QA_OPERATOR=<名前> pnpm run:sheet:web <シート.tsv>
```

これで消えたもの: 署名 / `xattr` の 1 行 / GitHub Release / 版番号の説明。
**そして直したものが `git pull` で届く。**アルファ版の間はこちらのほうが速い。

割符は**渡す道ではない**（README を読んだ: 2 人の映像と文字、会議キー、同じ網の中、
**ファイルは送れない**）。**初回に立ち会う道**として使う。**それ自体が割符の試験運用になる。**
