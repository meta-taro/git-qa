# 005 — ライブビューの遅延を実測する

- Phase: 1
- 前提: 004（一本道が通っていること）

## 目的

**遅延がそのまま体験の質になる。**

1〜2 秒遅れると、人には「AI が固まったのか、遅いだけなのか」が分からない。**分からないと人は手を出す。**そうなった時点で、この道具は目的を達していない。

## 決めること（このリポで決めてよい・企画側へ選択肢を投げ返さない）

- 許容できる遅延の上限（**先に決めてから測る**）
- 測り方（実機の画面と PC の画面を同時に撮る、タイムスタンプを重ねる 等）

## 作業内容

1. 上限を先に決めて書く
2. アプリのウィンドウ内に出ているライブビューの遅延を実測する
3. 上限を超えていた場合、原因を切り分ける（scrcpy 自体か / 埋め込み方式か / 描画か）
4. 超えたままなら Issue 003 の埋め込み方式に戻る

## 完了条件

- 実測値がある（1 回ではなく、複数回の分布）
- 上限以内に収まっている。**収まっていない場合、Issue 003 へ差し戻す判断が書かれている**
- **Appium のスクリーンショット連写を使っていないこと**（C4。遅すぎてライブにならない）

## 注意

- 数字が出ないうちに「体感で問題ない」と書かない。**人が待つかどうかを決めるのはこの数字**
- 測るのは「AI の操作が終わってから画面に出るまで」であって、AI の思考時間ではない
