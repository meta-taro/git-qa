# 016 — デスクトップアプリを検証する（手元にあるものが対象）

- Phase: 1
- 前提: 015（ウェブ検証。映像の運び方を共用する）
- 優先度: 高

## なぜ

**人の指示**（2026-09-06）:

> rust とかのデスクトップアプリ、ソフトウェアの検証はできますかね。この場合は、
> ローカルにあることが前提です。
>
> タウリですが、はなからしぼってきめないでほしいですが。どんなものでもできてほしいので。

**アプリの作りで線を引かない。**触れ方を段で持つ（C55）。

## 実測（2026-09-06・このマシン）

| | 実測 |
|---|---|
| 窓 1 枚を撮る | **118 ms / 枚**（約 8.5 fps）・**737 KB / 枚** |
| 段 1（アクセシビリティ）— warifu（Tauri） | **8 個 / 1,322 ms** |
| 段 2（絵から文字を読む）— 同じ窓 | **29 行 / 1,149 ms** |

**Tauri では段 2 のほうが速くて多い。**AX には浅くしか出てこない。
だから**読むときは両方見る**。触るときは段 1 を先に見る（名前が取れているならそちらが確か）。

## できたところ

- `packages/adapter-desktop` —— 窓を探す / 撮る / AX を読む / OCR を読む / 触る
- `pnpm run:sheet:desktop <シート.tsv>` —— シートを 1 本走らせる
- 見本シート `sheets/desktop-sample-ja.tsv`（対象は warifu）
- OCR は **OS の Vision** を呼ぶ 37 KB の実行ファイル 1 つ（`tools/ocr.swift`）。**依存は足さない**

## 途中で 2 回止まり、そのたびに直した（C40 と同じやり方）

1. `シートの見出し「# 対象:」が、パッケージ名でも URL でもない: warifu`
   → **行き先の書き方をアダプタが名乗る**ようにした（`AdapterCapabilities.appId`）。
   デスクトップはアプリ名そのもの。**表示名を通さないのは Android の事情**（C40）で、
   どのパッケージかが端末と地域で変わるのが理由。**その問題が無い相手に押し付けない**
2. **人からフォーカスを奪っていた。**実物を使った人の報告:
   「チャット欄に書き込もうとしてフォーカス当てると、実際のアプリに移動しちゃうね」。
   操作のたびに `activate()` していた。**検証は人の作業の上で走る。**
   前面に出すのは、シートが「起動する」と書いたときだけにした

## 止まっているところ（**人にしかできない**）

**アクセシビリティの許可。**実行中にこれが出た。

```
osascript が失敗した: System Events でエラーが起きました:
osascript には補助アクセスは許可されません。 (-25211)
```

**システム設定 → プライバシーとセキュリティ → アクセシビリティ**で、
git-qa を動かしているアプリ（ターミナル、または配布した `git-qa.app`）を許可する。
**許可したあと、そのアプリを一度終了して開き直すまで効かない**（画面収録のときと同じ）。

あわせて**画面収録の許可**も要る（窓を撮るため）。
