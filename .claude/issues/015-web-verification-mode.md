# 015 — ★ウェブ検証モード（直近の本命）

- Phase: 1
- 前提: 002（Adapter の境界）
- 優先度: **最高**

## なぜ今これか

**人がそう言ったから**（2026-09-06）。

> スマホ実機が本命ではあるものの、直近ひつようなのは、その PC のローカルないし、
> CF でアップしたウェブページです。
>
> なので、うごく／うごかないの確認は、その試験運用がいちばん効果的なんです。

roadmap の 17 行目に、こう書いてあった。

> **どちらも「作りやすい順」で並んでいる。**（…）**技術的な難易度で順番が決まっていて、
> 誰がいま困っているかが入っていない。**

**その「誰がいま困っているか」が出た。**順番を組み替える。

**この道具自身が動くかどうかの確認手段でもある。**Android 実機は用意と片付けが要るが、
ローカルのウェブページなら何度でも回せる。**試験運用の回数が増えることが、いちばん効く。**

## 対象

- PC のローカルで動いているウェブページ（`http://localhost:...`）
- Cloudflare へ上げたウェブページ（公開 URL）

## 既にある土台

架構は Web を織り込んで作ってある。**足すだけで済むはず**（C12）。

| | 状態 |
|---|---|
| `Target.kind` に `'web'` | ✅ ある |
| `ObservationKind` に `'dom'` | ✅ ある |
| `Target.browser` | ✅ ある |
| `screenSize?()` が任意（「取れない対象（Web など）は持たない」） | ✅ そう書いてある |
| 映像の運び方 | ⚠️ `h264-stream` と `external-window` しか無い |
| 手順の語彙 | ⚠️ タップ / 入力 / 起動。**Android の言い方**（C40） |

## 完了条件

- ローカルのページを開き、**git-qa の中央カラムにその画面が出る**
- 検証シートを 1 本走らせ、**人が判定を置いて `run.json` が出る**
- CF の公開 URL でも同じことができる
- **人が実物で 1 本通している**（AI の実測だけで「完了」と書かない）
