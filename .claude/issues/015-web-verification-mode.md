# 015 — ★ウェブ検証モード（直近の本命）

- Phase: 1
- 前提: 002（Adapter の境界）
- 優先度: **最高**

## なぜ今これか

**人がそう言ったから**（2026-09-06）。

> スマホ実機が本命ではあるものの、直近ひつようなのは、その PC のローカルないし、
> CF でアップしたウェブページです。
>
> なので、うごく／うごかないの確認は、その試験運用がいちばん効果的なんです。

roadmap の 17 行目に、こう書いてあった。

> **どちらも「作りやすい順」で並んでいる。**（…）**技術的な難易度で順番が決まっていて、
> 誰がいま困っているかが入っていない。**

**その「誰がいま困っているか」が出た。**順番を組み替える。

**この道具自身が動くかどうかの確認手段でもある。**Android 実機は用意と片付けが要るが、
ローカルのウェブページなら何度でも回せる。**試験運用の回数が増えることが、いちばん効く。**

## 対象

- PC のローカルで動いているウェブページ（`http://localhost:...`）
- Cloudflare へ上げたウェブページ（公開 URL）

## 既にある土台

架構は Web を織り込んで作ってある。**足すだけで済むはず**（C12）。

| | 状態 |
|---|---|
| `Target.kind` に `'web'` | ✅ ある |
| `ObservationKind` に `'dom'` | ✅ ある |
| `Target.browser` | ✅ ある |
| `screenSize?()` が任意（「取れない対象（Web など）は持たない」） | ✅ そう書いてある |
| 映像の運び方 | ⚠️ `h264-stream` と `external-window` しか無い |
| 手順の語彙 | ⚠️ タップ / 入力 / 起動。**Android の言い方**（C40） |

## 完了条件

- ローカルのページを開き、**git-qa の中央カラムにその画面が出る**
- 検証シートを 1 本走らせ、**人が判定を置いて `run.json` が出る**
- CF の公開 URL でも同じことができる
- **人が実物で 1 本通している**（AI の実測だけで「完了」と書かない）

## 作業ログ

### 2026-09-06 — 見て・触れて・読めるところまで通した（実測）

**ブラウザを起こし、ページを開き、絵を受け取り、押して、DOM に結果が出るまで**を実物で通した。

| | 実測値 |
|---|---|
| `https://example.com/` の絵 | **11,328 バイト**（JPEG 1 枚・実際に描かれている） |
| ローカル（`http://127.0.0.1:8731/page.html`）の絵 | **9,875 バイト** |
| DOM | `<html><head><meta charset="utf-8"><title>ローカルの見本</title>...`（310 文字） |
| 押した結果 | ボタンを押して `<p id="out">` が **「押された」** に変わった |
| スクリーンショット | 15,042 バイト PNG |

**依存は 1 つも足していない。**

### 途中で踏んだこと（実測でしか出なかった 3 つ）

1. **標準エラーには何も書かれない。**macOS の Chrome を直に起こすと、繋ぎ先を
   標準エラーに書かないまま起動する。20 秒待って落ちた。
   **`DevToolsActivePort` を読む形に変えた**（そちらが正式な口）
2. **背面のタブは画面を配れない。**`Page.startScreencast を断られた:
   Not attached to an active page`。**`Page.bringToFront` を先に呼ぶ**
3. **静的なページは絵が 1 枚しか来ない。**変わらないのだから当然だが、
   確認スクリプトが 3 枚待って固まった。**「来ない」と「壊れた」は別**

### 同日 — **中央カラムに、動くページが出た**

```
pnpm live:web http://127.0.0.1:8731/clock.html
```

git-qa の中央カラムに、ローカルのページがそのまま出た。**時計のページで確かめた。**

| 撮った時刻 | 画面に出ていた時計 |
|---|---|
| 1 回目 | **13:00:34** |
| 2 回目 | **13:00:39** |

**進んでいる。**「1 枚出た」ではなく、ライブで流れている。

- 画面側は `createImagePlayer`（`packages/desktop/src/live/images.ts`）。**復号器は要らない**
  —— 揃った 1 枚を `createImageBitmap` で絵にして描くだけ
- **どちらの映像かは画面側では決められない。**Node 側が `?livekind=images` で知らせる。
  知らせないと、画面はブラウザの絵を H.264 として復号しようとする
- 実寸の名前が 2 つある（`VideoFrame` は `displayWidth`、`ImageBitmap` は `width`）。
  **両方見る**ようにした。片方だけだと canvas の大きさが合わず、絵が歪む

### 同日 — **シートを 1 本、最後まで通した**

```
pnpm run:sheet:web sheets/web-sample-ja.tsv
```

見本のシート 3 件が**すべて PASS**（`runs/20260906-160022/run.json`）。

| No. | 手順 | AI の判定 | 根拠 |
|---|---|---|---|
| 1 | ページを起動する | PASS | 画面の文字に「ローカルで動いているページ」が在る |
| 2 | ページを起動する | PASS | 画面の文字に「まだ押されていない」が在る |
| 3 | **「押す」をクリックする** | PASS | 画面の文字に「押された」が在る |

**3 件目が本番。**文字で要素を見つけて押し、その結果を読んでいる。

**判定はすべて `AUTO_PASS`。**AI が `Space`（置かずに次へ）で送っただけで、
**人は 1 件も見ていない。**証跡にもそう残っている（`3 件中 0 件を人が見て置いた`）。

### 途中で 2 回止まり、そのたびに直した（C40 と同じやり方）

1. **1 件目で止まった。**`どのアプリを起動するか決められない: ページ`。
   Android のパッケージ名しか通していなかった。**「ページを開く」と URL を通した**
2. **3 件目で止まった。**`ウェブではまだ座標でしか触れない（来たもの: element）`。
   **文字から要素を探す道を足した**（名乗り → 完全一致 → 含む。いちばん内側を選ぶ）

**どちらも実物のシートを走らせるまで出なかった。**
