# 004 — ★Android で一本道を通す（最初の山）

- Phase: 1
- 前提: 002 / 003 / 006
- 優先度: **最高**

## 目的

**この製品が解こうとしている問題が実物で見える状態を作る。**

> **TSV を読み込み、Android 実機を AI が操作し、人が横でライブで見て、1 打鍵で `VERIFIED` を置き、`run.json` が出るまで。**

## 通す流れ

```
TSV を読む（書き戻さない）
 → Android 実機に接続
 → scrcpy のライブビューが画面中央に出る
 → AI がケースを実行する（人は横で見ている）
 → AI が「判断保留」と言う / 落ちる / 差分が出る
 → 人が 1 打鍵で VERIFIED を置く
 → 次のケースへ自動で進む
 → runs/<ts>/<caseId>/ に証跡が出る
```

## 決めること（このリポで決めてよい・企画側へ選択肢を投げ返さない）

- AI が「判断保留」を出す条件
- 人が押すキーの割り当て
- ケース間の遷移（自動で進むか、1 拍置くか）

## 完了条件

- **5 ケース以上**をこの流れで通せる
- `run.json` に `VERIFIED` と `AUTO_PASS` が**混在している**（全部人が見る運用になっていないこと）
- **`VERIFIED` を置くのが 1 打鍵**で、押したら次のケースへ進む（C6）
- **合否は人が置く。AI が `VERIFIED` を宣言しない**
- TSV が**書き換わっていない**（C3。実行前後で `git diff` に出ないこと）

```bash
git diff --name-only   # TSV が出ないこと
```

## 作業ログ

### 2026-09-02 — Android アダプタを置いた（一本道はまだ通っていない）

**この Mac に Android Studio の SDK と AVD が既にあった。**Pixel 3a / API 31 を `-no-window` で
起動し（14 秒）、scrcpy 4.1 と adb を入れて繋いだ。**実機ではないが、adb と scrcpy の相手としては
本物。**

#### 置いたもの: `packages/adapter-android`

**Adapter は差し替える前提なので別パッケージにした**（product-baseline §9）。

- `command.ts` — adb / scrcpy を呼ぶ口を**注入できる形**にした。本物の起動は
  `node-runner.ts` の向こう側だけに置く
- `adb.ts` — **プロセスを起動しない純粋な部分**（引数の組み立て・端末一覧の解析・
  `input text` の escape・uiautomator の dump から座標を出す）
- `adapter.ts` — `TargetAdapter` の実装。connect / act / observe / screenshot /
  liveView（scrcpy の窓）/ recording（scrcpy の `--record`）

#### 検査

| | 件数 | 端末 |
|---|---|---|
| 純粋なロジック（`adb.test.ts`） | 22 | 不要 |
| アダプタ（`adapter.test.ts`・**契約テストを含む**） | 30 | 不要（adb / scrcpy を差し替え） |
| 実機（`device.e2e.test.ts`） | 4 | **要**（`GIT_QA_ANDROID_E2E=1` のときだけ走る） |

**全体で 173 件・全て通過。**端末が無い環境では実機の 4 件が飛んで 169 件が通る
（product-baseline §4「繋がらない環境でも走る形にする」）。

実機の 4 件で確かめたこと: 繋いで型番と OS の版が取れる / uiautomator の XML が取れる /
PNG が取れる（署名とサイズを確認）/ **操作すると画面が実際に変わる**。

#### テストが実装のバグを 1 つ捕まえた

`findElementCenter` に空文字を渡すと、`resource-id=""` のノード（画面上に多数ある）に
当たってしまっていた。**しかも「最初に見つかった何か」を掴むので間違いに気づけない。**
空の参照を弾くようにした。

#### 決めたこと（Issue の「決めること」のうち 1 つ）

- **要素の指定は完全一致のみ**（`resource-id` → `text` → `content-desc` の順）。
  部分一致にすると、画面が変わったときに別の要素を掴んで、しかも気づけない
- **非 ASCII の `input text` は落とす。**端末の `input text` は IME を経由しないので日本語を
  送れない。黙って化けた文字を打つより、送れないと言うほうがよい
- **ライブビューと録画は別プロセス。**人が窓を閉じても録画は続くべきで、逆も同じ
- **端末が複数見えていて serial の指定が無ければ、選ばずに落とす。**黙って 1 台目を選ぶと、
  証跡に書いた相手と実際に触った相手がずれる

### 2026-09-02（続き）— 端末の映像を画面へ出す道を通した

一本道の前提として、**端末 → 画面へ映像を運ぶ経路**を作った。ここが無いと、人が横で見る
という前提（C4）が成立しない。

- **映像の取り出し方を決めた**（C32 / ADR 0003）。`adb exec-out screenrecord` の生 H.264。
  scrcpy のサーバへ直接繋ぐ案は「scrcpy の再実装」に近づくので採らず、**安いほうを先に実装して
  測る**という順にした
- **受け手を製品側へ移した**（`packages/desktop/src/live/`）。スパイクで 2 回壊れた
  アクセスユニット境界の判定を、テストで固定した
- **橋を作った**（`packages/live-bridge`・C33）。127.0.0.1 のみ・URL に無作為の 32 文字
- **宿主を作った**（`packages/host`）。`pnpm live` で 端末に繋ぐ → 橋を起こす →
  `?live=<url>` で Tauri を起動する

**実測で確かめた所**

| | 結果 |
|---|---|
| アダプタが端末に繋ぐ | ✅ `screenrecord` が動く |
| 橋が映像を流す | ✅ **6 秒で 2,818,048 バイト** |
| Tauri が正しい設定で起動する | ✅ `devUrl` に `?live=` が載っている |
| webview がページを読み込む | ✅ vite への接続が張られる |
| **webview が橋に繋いで描く** | ❌ **未確認** |

**最後の 1 マスが埋まらないのは、画面がロックされているため。**ロック中はアプリが動かず、
vite が page reload を送っても反応が返らない。**人がロックを解いて `pnpm live` を実行する
必要がある**（§29）。

**途中で CSP の穴を 1 つ見つけて直した。**`default-src 'self'` は `connect-src` にも効くので、
`localhost:1420` のページから `127.0.0.1:<port>` の橋へは繋げなかった。入れた CSP が正しく
働いた結果で、`connect-src 'self' http://127.0.0.1:*` を足した（テストで固定）。

**映らない理由を画面に出すようにした**（`showLiveViewError`）。console だけだと人には見えず、
待ち続けることになる。

**この Issue の本体（一本道）は、まだ 1 度も走っていない。**
