# 008 — ★手作業と比べて楽になったかを数字で出す（主指標）

- Phase: 2
- 前提: 004（一本道が通っていること）/ 009（実案件が決まっていること）
- 優先度: **最高**

## 目的

**この製品の生死を決める数字を出す。**

初期の企画草案 §22 の MVP 成功条件に「従来の手動チェックより明確に楽」とあるが、主観のままでは判定できない。

> **同じ 20 ケースを、手で通した所要時間と、この道具で通した所要時間。後者が明確に短いこと。**

**他が全部できていても、この数字が出なければ MVP ではない。**

## 決めること（このリポで決めてよい・企画側へ選択肢を投げ返さない）

- 「明確に短い」の基準（何割減なら合格とするか。**先に決めてから測る**）
- 測定の手順（同じ人が両方をやるのか、別の人か）

## 作業内容

1. 基準を先に決めて書く
2. Issue 009 で決まった実案件のケースを、**人が手で通して時間を測る**
3. 同じケースをこの道具で通して時間を測る
4. あわせて手数を数える（1 ケースあたりの打鍵数・マウス操作回数）
5. 差が出なかった場合、どこで時間を食っているかを切り分ける

## 完了条件

- 両方の所要時間の実測値がある
- 手数の実測値がある
- 基準を満たしている。**満たしていない場合、どこで時間を食っているかが特定され、UI の作り直しが Issue になっている**

## 注意

- **AI の思考時間も人の待ち時間に入る。**ASSIST は人が横で見ているので、AI が遅いことはそのまま人の待ち時間になる。ここを測定から外さない
- 「慣れれば速くなる」で片付けない。**初回で遅いなら、初回で遅いと書く**
- 数字が悪かったときに、**測り方を変えて良く見せない**
