# 011 — 画面に「次に何をすればよいか」を出す（案内ウィザード）と多言語対応

- Phase: 1
- 前提: 004（一本道）
- 起票: 2026-09-02。**実物を触った人からの指摘**

## 何が起きたか（実物）

一本道（Issue 004）を初めて人が触った。第一印象は「おぉ、なるほど」。そのうえで **2 つ**指摘が出た。

1. **メニューが英語になっている。**画面の中は日本語なのに、OS のメニューバーだけ英語
2. **「検証シートの読み込み方も、Android の接続の仕方も分からない」。**
   アプリを開いても、次に何をすればよいかが画面から分からない

**2 つ目が本質。**いまの入口は `pnpm run:sheet <検証シート.tsv>` で、**端末を繋ぐのも
シートを選ぶのも、ターミナルを知っている人しかできない。**README に書いても開かれない。

## 決めたこと

| | 決めたこと |
|---|---|
| 対応言語 | **日本語（既定）＋ 英語（fallback）**。OS のロケールで決め、`GIT_QA_LANG` で上書き |
| 英語メニュー | Tauri の既定メニューが出ているだけ。**自前の日本語メニューに差し替える** |
| 案内の置き場 | **アプリの中**。README でもターミナルの対話でもない |
| 順番 | **多言語 → ウィザード**。ウィザードの文言も同じ仕組みに載せるため |

**採らなかった案**: `pnpm run:sheet` を引数なしで実行したときの対話ウィザード。安いが、
**困ったのはアプリを開いた後**なので、そこに置かないと意味がない。

## 段階

### 段階 1 — 文言を 1 箇所に集め、既定を日本語にする

- 画面の文言をカタログ（ja / en）に集める。**ハードコードした日本語を残さない**
- ロケールの決め方を 1 箇所に閉じる（`navigator.language` / `GIT_QA_LANG`）
- ネイティブメニューを自前の日本語に差し替える（Rust 側）

### 段階 2 — 「いま何が足りないか」を画面に出す

実行に繋がっていないときのアプリは、いま空の 3 カラムが出るだけ。ここを案内にする。

- 端末に繋がっているか / シートを読んでいるか / 実行中か を出す
- 繋がっていないなら、**次にやることを 1 つだけ**出す

### 段階 3 — アプリから接続し、シートを選び、実行を始められる

**入口をアプリ側へ移す。**いまは Node の CLI が入口で、アプリはそれに従属している。

- 端末の一覧をアプリから見て、選べる
- 検証シートをアプリから選べる（ファイル選択）
- 「実行を始める」を押すと走り出す

**これはアーキテクチャの変更を含む**（Node 側に、接続前から待つ口が要る）。
段階 2 までとは別に見積もる。

## 完了条件

- アプリを初めて開いた人が、**ターミナルを見ずに**端末の接続まで辿り着ける
- 画面とメニューに、ハードコードされた文言が残っていない
- 言語を切り替えると、画面とメニューの両方が変わる
- **判定は人が置く**という前提を、案内が壊していない（AI が代わりに押す導線を作らない）

## 注意

- **色・タイポグラフィは決めない**（`DESIGN.md` が空・§11）。案内は文言と構造だけ
- 段階 3 で入口が変わっても、`pnpm run:sheet` は残す（自動実行と検査に要る）
