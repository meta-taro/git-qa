# 007 — 証跡の保管と、録画ありで運用したときの費用

- Phase: 3
- 前提: 006（run.json のスキーマ）

## 目的

証跡を Git に残す方法を決め、**録画ありで運用したときの保管費の上限**を出す。

## 判断材料

- **録画は開始時の設定**（C11）。常時発生する原価ではないので、「on で運用したときの上限」だけ分かればよい
- 動画は 1 ケース 1 本。1 回の Run で数十本になる
- GitHub の Git LFS は無料枠が小さく、**超えると利用者が自分のリポで課金を食らう**
- 自社は納品物として使うので案件原価として説明がつくが、**OSS 利用者にはそのまま降りる**

## 決めること（このリポで決めてよい・企画側へ選択肢を投げ返さない）

- 大容量ファイルの置き方（Git LFS / 別ストレージ / commit しない選択肢を用意する）
- 既定値（録画 on / off のどちらを既定にするか）
- 古い Run の扱い（残す / 間引く / 利用者に任せる）

## 作業内容

1. 実測から 1 ケースあたりの動画サイズを出す
2. 「20 ケース × 1 日 1 回 × 1 か月」など、現実的な運用での月間容量を出す
3. Git LFS の料金に当てて月額を出す
4. 高すぎる場合の逃げ道を用意する（動画を commit しない設定など）

## 完了条件

- 月間容量と月額の試算がある（**一次情報の料金表を参照していること**。推測で書かない）
- 既定値が決まっていて、その理由が書かれている
- **動画を Git に入れない運用でも製品が成立する**ことが確認できている

## 注意

- 設定を無くして「常に録画」にしない。**どのモードで録画が要るかを決めるのは人**（C11）
- 費用を理由にライブビューや証跡そのものを削らない。**削るのは動画の保管方法だけ**

#### 容量の試算

前提（**すべて仮定。実機が無いので実測ではない**）

- scrcpy の既定ビットレート **8 Mbps**（一次情報: scrcpy の `doc/video.md` "The default video bit rate is 8 Mbps."）
- 1 ケース **60 秒**
- **20 ケース / 回・1 日 1 回・20 営業日**

| | 値 |
|---|---|
| 8 Mbps | 60 MB / 分 |
| 1 ケース（60 秒） | 60 MB |
| 20 ケース | **1.2 GB / 回** |
| 20 営業日 | **24 GB / 月** |
| 無料枠 10 GiB（= 10.74 GB） | **8.9 回（約 9 営業日）で尽きる** |
| Team 250 GiB（= 268 GB） | **11.2 か月で尽きる** |

**控えめに 2 Mbps としても 6 GB / 月**で、無料枠まで 1.8 か月。

**ストレージは累積する。**Git の履歴に入る以上、2 か月目は 48 GB、3 か月目は 72 GB。
**減るのは履歴を書き換えたときだけ。**

**帯域はもっと早く尽きる。**LFS を有効にしたリポを新しく clone すると、その時点の LFS
オブジェクトをまとめて取得する。**24 GB の履歴を 1 回 clone しただけで、月間帯域 10 GiB を
超える。**開発者が 1 人増えるたびに起きる。

#### 合成映像での実測は使いものにならなかった

ffmpeg で作った合成映像（1080x2340 / 30fps / 60 秒）で 1 ケースあたりのサイズを測ろうとした。

| 内容 | 実測 |
|---|---|
| 静止背景＋小さな動く領域 | 0.34 Mbps（2.42 MB / 分） |
| 画面全体が動き続ける | 7.52 Mbps（53.76 MB / 分） |
| リスト画面のスクロール | 0.10 Mbps（0.71 MB / 分） |

**この数字は採らない。**合成映像には文字やアイコンの質感が無く、実際の画面より遥かによく
圧縮される。スクロールが最も小さくなっているのがその証拠（実機では逆に大きくなる）。
**上の試算は「scrcpy に設定したビットレートの上限」で置いた。**実機の scrcpy で録ったものを
測るまで、下限側は分からない。

### 2026-09-02（追記）— Android エミュレータで実測した。上の見積りは 11 倍過大だった

**Android エミュレータ（Pixel 3a / API 31 / arm64）が既にこの Mac にあった**ので、
scrcpy で実際に録画して測り直した。**上の「合成映像では測れない」という結論は正しかったが、
代わりに置いた 8 Mbps の上限は実態から大きく外れていた。**

#### 実測（scrcpy 4.1・`--record`・実時間 60 秒・設定画面をスクロールし続けた）

| | 値 |
|---|---|
| 解像度 / codec | 1080x2220 / H.264 |
| ファイル | **5.05 MB**（実時間 60 秒ぶん） |
| 映像の長さ | 33.0 秒 / **平均 10 fps** |
| ビットレート | **1.28 Mbps**（映像区間）/ **0.71 Mbps**（実時間平均） |

**scrcpy は画面が変化したときしかフレームを作らない。**スクロールを止めた時点で映像は 33 秒で
止まっており、残りの 27 秒はほぼ 0 バイト。**8 Mbps は上限であって、実際に出る値ではない。**

**これは製品にとって効く性質。**容量は実時間ではなく**画面が変化した量**に比例する。
人が考えている時間・AI が待っている時間は、ほぼ容量を食わない。

#### 直した試算

| | 前回（8 Mbps 上限） | **実測ベース** |
|---|---|---|
| 1 ケース（実時間 60 秒） | 60 MB | **5.05 MB** |
| 20 ケース / 回 | 1.2 GB | **106 MB** |
| 20 営業日 | 24 GB / 月 | **2.12 GB / 月** |
| 無料枠 10 GiB まで | 約 9 営業日 | **累積で 5.1 か月** |
| Team 250 GiB まで | 11.2 か月 | **累積で 127 か月** |

**前回の見積りは 11 倍過大だった。**

#### この実測の弱いところ

- **実機ではなくエミュレータ。**GPU は swiftshader で、実機より描画が単純になっている可能性がある
- **設定画面のスクロールだけ。**写真・動画・アニメーションの多い実アプリはもっと出る
- **API 31 の 1 端末のみ。**端末とエンコーダ設定で変わる
- したがって**実機の実アプリはこの値より大きい。**上限 8 Mbps と実測 0.71 Mbps の間のどこか

#### 決定は変わるか

**変わらない。ただし緊急度と理由の重心が変わる。**

- **ストレージは Git の履歴に入る以上、青天井に累積する。**月 2.12 GB でも、無料枠なら 5 か月で尽きる。
  **どんなに小さい月次でも、固定枠はいつか超える**
- **帯域のほうが依然として先に破裂する。**5 か月ぶん（10.7 GB）を溜めたリポを**1 回 clone しただけで、
  月間帯域 10 GiB を超える**
- **Team / Enterprise Cloud（250 GiB）なら 10 年以上もつ。**そちらでは LFS は現実的な選択肢

→ **既定は「入れない」のまま**（OSS 利用者と Free / Pro を課金経路に乗せない）。
**ただし「LFS は無理」ではなく「Team 以上なら現実的」と書き直す。**

#### 動画を Git に入れない運用でも製品が成立するか（完了条件 3）

**成立する。**`packages/core` の `CaseRecording` は既に 4 状態（C20）で、
`{ state: 'not_requested' }` を持つ。`test/run/end-to-end.test.ts` が**録画あり / なしの 2 回**を
走らせて `run.json` を読み返しており、録画が無くてもケースの合否と証跡は残る。

## 結果

**決めたこと**（詳細と理由は `.claude/decisions.md` C29）

1. **動画は既定で Git に入れない。**`runs/` を `.gitignore` に入れ、ローカル保管を既定にする
2. **録画そのものの既定は on。**保管が Git の外なら、費用は課金ではなくディスク。off にする口は必ず出す（C11）
3. **古い Run を自動で消さない。**消すのは人の判断
4. **Git LFS はオプトイン。**使う場合の試算（上表）と、単価は料金計算機で確認することを文書に書く。
   **Team / Enterprise Cloud（250 GiB）なら実測ベースで 10 年以上もつ**ので、そちらでは現実的な選択肢

**まだ満たしていない完了条件**

- 「月額の試算がある（一次情報の料金表を参照していること）」— **超過単価が一次情報から取れていない。**
  既定を「入れない」にしたので**既定の月額は 0** だが、オプトインした利用者向けの月額は出せていない。
  料金計算機（ブラウザが要る）を人が確認する必要がある
- ~~1 ケースあたりの動画サイズは実測ではなく上限での見積り~~ → **2026-09-02 にエミュレータで実測した**
  （5.05 MB / ケース・上の追記）。**ただし実機ではない。**実機の実アプリはこれより大きい
